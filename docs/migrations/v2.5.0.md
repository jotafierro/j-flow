# Migration Guide

## 2.4.x → 2.5.0

**Nothing in 2.5.0 breaks.** No command was renamed or removed, and every existing `.specs/` artifact stays valid. The new configuration (`.specs/config.md`) is optional — its absence means the 2.4.x defaults, so a project that ignores this guide keeps behaving exactly as before.

**But updating the plugin does not fix your repo.** Most of 2.5.0 is bug fixes in `/j-flow-scaffold`, and a scaffold runs once. A project generated with 2.4.x or earlier still carries those bugs in its own files, and nothing in the plugin will retroactively edit them: growth re-runs are create-if-missing with carry-forward, precisely so they never overwrite what you may have hand-edited.

So this guide is a **retrofit checklist**, not a list of breaking changes.

### Update the plugin

```bash
git -C ~/j-flow pull && claude plugin update j-flow
```

### `/j-flow-scaffold --review` will not tell you any of this

That mode reports file presence (`✓ present` / `✗ missing`) plus a few content heuristics. It never runs `pnpm install`, `lint`, or `test`, so a `package.json` with a broken script reads as `✓ present`. Use the checklist below instead.

### Detect everything at once

Run this from your project root. It reads your manifests — no install required:

```bash
node -e '
const fs=require("fs"), path=require("path");
const manifests=[["package.json"]].concat(["packages","apps"].map(d=>
  fs.existsSync(d)?fs.readdirSync(d).map(n=>path.join(d,n,"package.json")):[]))
  .flat().filter(f=>fs.existsSync(f))
  .map(f=>({f, p:JSON.parse(fs.readFileSync(f,"utf8"))}));

console.log("1) packages running oxlint without declaring it");
const noOx=manifests.filter(({p})=>p.scripts?.lint==="oxlint" && !(p.devDependencies?.oxlint||p.dependencies?.oxlint)).map(({p})=>p.name);
console.log("   "+(noOx.length?"FAIL "+noOx.join(", "):"ok"));

console.log("2) apps/e2e Playwright script");
const e2e=manifests.find(({f})=>f==="apps/e2e/package.json");
if(!e2e) console.log("   - no e2e layer");
else {
  const s=e2e.p.scripts||{};
  console.log("   scripts: "+JSON.stringify(s));
  console.log("   "+(s.e2e?"ok":"FAIL missing e2e script"));
  if(/no test specified/.test(s.test||"")) console.log("   FAIL still carries npm init placeholder - pnpm test and CI fail");
  const pw=(e2e.p.devDependencies||{})["@playwright/test"];
  console.log("   @playwright/test: "+(pw?"ok "+pw:"FAIL not declared"));
}

console.log("3) declared versions per shared dependency");
for(const dep of ["typescript","react","react-dom","oxlint","vitest","@types/node"]){
  const seen=new Map();
  for(const {f,p} of manifests) for(const sec of ["dependencies","devDependencies"]){
    const v=p[sec]?.[dep]; if(v) (seen.get(v)||seen.set(v,[]).get(v)).push(p.name||f);
  }
  if(!seen.size) continue;
  const distinct=[...seen.keys()], literal=distinct.filter(v=>v!=="catalog:");
  const flag = distinct.length>1 ? "FAIL split" : (literal.length&&seen.get(literal[0]).length>1 ? "FAIL repeated literal" : "ok");
  console.log("   "+dep.padEnd(13)+flag+"  "+distinct.map(v=>v+" ("+seen.get(v).length+")").join("  "));
}

console.log("4) turbo e2e task / root script");
const t=JSON.parse(fs.readFileSync("turbo.json","utf8")).tasks||{};
const r=JSON.parse(fs.readFileSync("package.json","utf8")).scripts||{};
console.log("   turbo e2e: "+(t.e2e?"ok":"FAIL")+"   root script e2e: "+(r.e2e?"ok":"FAIL")+"   turbo test:e2e absent: "+(t["test:e2e"]?"FAIL present":"ok"));
'
```

Verified against both a 2.5.0 scaffold (all `ok`) and a 2.4.x one (flags 1, 2, 3 and 4).

---

### 1. Declare `oxlint` where a `lint` script runs it

**Symptom:** `pnpm lint` dies with `sh: oxlint: command not found`. Under pnpm's isolated `node_modules` only a package's own dependencies reach its `.bin`, and the 2.4.x scaffold gave `packages/domain`, `packages/api-client`, `packages/ui` and `apps/cli` a `"lint": "oxlint"` script without the dependency. `apps/web` and `apps/admin` worked by accident — `create-vite` declares it for them.

**Fix:** add `"oxlint": "catalog:"` (or a literal range if you skip step 3) to the `devDependencies` of every package the detector flagged.

**Verify:** `pnpm lint` — every package should report a task, not an error.

### 2. Give `apps/e2e` a Playwright script, and keep it out of `pnpm test`

**Symptom:** `pnpm test` and CI fail. `create-playwright` never writes its scripts here, leaving `npm init`'s `"test": "echo \"Error: no test specified\" && exit 1"` — and turbo maps the root `test` task onto every package's `test` script.

**Fix** in `apps/e2e/package.json` — replace the `test` placeholder entirely:

```json
"scripts": {
  "e2e": "playwright test",
  "e2e:headed": "playwright test --headed",
  "report": "playwright show-report",
  "type-check": "tsc --noEmit"
}
```

Do **not** name it `test`: that puts a browser and a booted web server inside the command `/j-flow-qa` runs at every gate. Do not name it `test:e2e` either — `@nestjs/cli` already uses that in `apps/api` for its supertest suite, and turbo resolves tasks by name, so one task would run both suites.

Also ensure `"@playwright/test": "catalog:"` is in its `devDependencies`, and delete any `devEngines` block (`create-playwright` writes a range there that later pnpm commands reject).

**Fix** in `turbo.json` — add the task:

```json
"e2e": { "cache": false }
```

**Fix** in the root `package.json` — add the script: `"e2e": "turbo e2e"`.

**Verify:**

```bash
pnpm test    # must pass, and must not mention playwright or chromium
pnpm e2e     # must actually run Playwright
```

### 3. Move shared versions into the catalog

**Symptom:** the detector reports `FAIL split` or `FAIL repeated literal`. A 2.4.x scaffold declares `typescript` literally in up to five places while `create-vite` pins its own — leaving two TypeScript majors in one workspace — and `react` can resolve to two copies across `packages/ui` and the app that renders its components, which fails at runtime with "invalid hook call".

**Fix** in `pnpm-workspace.yaml` — add the block, keeping only the entries whose packages you actually have:

```yaml
catalog:
  typescript: ^5.9.0
  oxlint: ^1.78.0
  "@types/node": ^24.13.3
  react: ^19.2.8
  react-dom: ^19.2.8
  "@types/react": ^19.2.17
  "@types/react-dom": ^19.2.3
  vitest: ^4.1.10
  playwright: 1.62.1
  "@playwright/test": 1.62.1
```

Then replace each declaration of those packages with `"catalog:"` across every `package.json`, **including the ones the CLIs generated** — `apps/web`'s `typescript`, `react`, `react-dom`, `@types/react`, `@types/react-dom`, `oxlint`, `@types/node`, and `apps/api`'s `typescript` and `@types/node`. Missing those is how the split survives.

`typescript` stays on 5.x deliberately: a NestJS 11 project does not build under TypeScript 6 (`TS5011`, `TS5101`, both against the tsconfig its own CLI writes). If `apps/web` was on `~6.0.2`, this is a downgrade — verified safe, the Vite template type-checks and builds on 5.9.3.

Leave `vite` and `@vitejs/plugin-react` alone. They are build-time only in separately built packages, with no shared runtime instance to keep identical.

**Verify:**

```bash
pnpm install
pnpm why typescript   # "Found 1 version"; same for react, react-dom, oxlint, vitest
```

### 4. Resolve `allowBuilds` placeholders

**Symptom:** every `pnpm run` fails — not just the install. pnpm ≥10 will not run a dependency's install script unasked, and pnpm 11 rewrites `pnpm-workspace.yaml` with `set this to true or false` entries, then blocks on them via the dependency-status check it runs before each script.

**Fix** in `pnpm-workspace.yaml`:

```yaml
allowBuilds:
  esbuild: true
  bufferutil: false
  utf-8-validate: false
  unrs-resolver: false   # if you have apps/api
```

`bufferutil` and `utf-8-validate` are optional native accelerators for `ws` (arriving via `vite`); `unrs-resolver` comes through the ESLint toolchain `@nestjs/cli` generates. Declining all three costs no functionality — measured.

For anything else pnpm adds later, resolve to **`false`** unless something demonstrably breaks without that build. A `true` lets a third-party install script run unsandboxed, so treat it as the supply-chain decision it is. Never reach for a blanket allow-all.

**Verify:**

```bash
pnpm install
grep "set this to true or false" pnpm-workspace.yaml   # no output
pnpm lint                                              # runs at all
```

Commit the resolved file — it is how the next person avoids the same stop.

### 5. Replace invented dependency versions

2.4.x told the model to add ten dependencies "at real version ranges", so two scaffolds of the same `PRODUCT.md` produced different `package.json` files. Nothing to fix in an existing repo — whatever you got is pinned in your lockfile. Worth knowing only if you compare two projects and wonder why they differ.

## What needs no action

| Feature | Why nothing to do |
|---|---|
| `.specs/config.md` | Absent means `Workflow mode: team`, `Spec language: en`, `Docs language: en` — the 2.4.x behavior. Create it (or run `/j-flow-project --update`, which backfills it) only when you want to change something. |
| `**Workflow mode:** solo` | Opt-in. Nothing changes until you set it. |
| Language contract | Both language fields default to `en`. Existing specs are untouched; the contract applies to newly written prose. |
| `[FINISH]` gate block | Applies forward. Features already finished keep their six blocks — the missing finish block is not backfilled, in line with the plugin's rule against rewriting history. |
