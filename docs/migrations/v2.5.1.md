# Migration Guide

## 2.5.0 → 2.5.1

Three scaffold fixes, all in profiles introduced by earlier releases and none of them repaired by updating the plugin — a scaffold runs once. If you are coming from 2.4.x, read [v2.5.0.md](v2.5.0.md) as well; this guide only covers what 2.5.1 adds.

Two of the three affect **only** projects on specific profiles. Run the detector; if it says "skip" for both, you have nothing to do.

### Update the plugin

```bash
git -C ~/j-flow pull && claude plugin update j-flow
```

### Detect

From your project root:

```bash
node -e '
const fs=require("fs");
const pkg=fs.existsSync("package.json")?JSON.parse(fs.readFileSync("package.json","utf8")):{};
const hasWs=fs.existsSync("pnpm-workspace.yaml");

console.log("A) bare-single-package profile");
if(fs.existsSync("apps")||!pkg.bin) console.log("   - not this profile, skip");
else console.log(hasWs ? "   ok pnpm-workspace.yaml present"
                       : "   FAIL no pnpm-workspace.yaml - pnpm install exits 1 and every pnpm run fails");

console.log("B) e2e external-target baseURL fallback");
const cfg="apps/e2e/playwright.config.ts";
if(!fs.existsSync(cfg)) console.log("   - no e2e layer, skip");
else {
  const s=fs.readFileSync(cfg,"utf8");
  if(/webServer\s*:/.test(s)) console.log("   - has webServer (has_web project), the fallback is correct here");
  else console.log(/BASE_URL\s*\?\?/.test(s)
    ? "   FAIL external-target config keeps a localhost fallback - an unset BASE_URL passes green against whatever answers there"
    : "   ok no fallback");
}

console.log("C) turbo e2e task passes BASE_URL through");
if(!fs.existsSync("turbo.json")||!fs.existsSync(cfg)) console.log("   - not applicable, skip");
else {
  const t=JSON.parse(fs.readFileSync("turbo.json","utf8")).tasks||{};
  const e=t.e2e;
  console.log(!e ? "   - no e2e task, skip"
    : (e.env||[]).includes("BASE_URL")||(e.passThroughEnv||[]).includes("BASE_URL")
      ? "   ok BASE_URL declared" : "   FAIL BASE_URL not declared - turbo runs the task without it");
}
'
```

Verified against four real repos: a fixed bare project, a broken one, an external-target e2e project, and a workspace with neither profile.

---

### A. `bare-single-package` cannot install

**Applies to:** a CLI-only project you told the scaffold was terminal — flat `src/` at the root, no `apps/`, no workspace files.

**Symptom:** `pnpm install` exits 1 with `ERR_PNPM_IGNORED_BUILDS: esbuild`, and because pnpm runs a dependency-status check before every script, `lint`, `test` and `build` all fail too.

**Cause:** the profile emits no `pnpm-workspace.yaml`, and pnpm 11 no longer reads the `pnpm` field in `package.json` (it warns and ignores it), so there was nowhere to declare `allowBuilds`. `esbuild` arrives through `tsup`, which this profile always generates.

**Fix:** create `pnpm-workspace.yaml` at the root with settings only — no `packages:` list:

```yaml
allowBuilds:
  esbuild: true
```

A "workspace" file in a repo with no workspace looks wrong, and is nonetheless where pnpm 11 keeps these settings.

**Verify:**

```bash
pnpm install   # exit 0
pnpm build     # exit 0
```

### B. An e2e-only project can pass green against something else

**Applies to:** a project with `apps/e2e` and **no** `apps/web` — the external-target profile, where `playwright.config.ts` has no `webServer` block.

**Symptom:** none, which is the problem. `pnpm e2e` reports a passing suite while testing an application that has nothing to do with your repo.

**Cause:** the config kept `baseURL: process.env.BASE_URL ?? 'http://localhost:3001'`. This profile serves nothing on 3001, so with `BASE_URL` unset Playwright navigated to whatever else on the machine answered there. Reproduced here against an unrelated project's dev server: one passing test, zero relationship to the repo under test.

**Fix** in `apps/e2e/playwright.config.ts` — drop the fallback:

```ts
use: { baseURL: process.env.BASE_URL, trace: 'on-first-retry' },
```

Keep the fallback if your project **does** have `apps/web`: there the local dev server is real and the `webServer` block boots it.

**Verify:**

```bash
pnpm e2e                                   # with BASE_URL unset: must now FAIL
BASE_URL=http://your-target pnpm e2e       # must pass
```

The failure reads `Cannot navigate to invalid URL`. That is the correct outcome — an unset target should stop, not silently succeed.

### C. `turbo` never passed `BASE_URL` to the e2e task

**Applies to:** any project with an `e2e` turbo task — which in practice means the external-target profile, since that is the one that needs the variable.

**Symptom:** `BASE_URL=… pnpm e2e` behaves as if `BASE_URL` were unset. With fix B applied it fails outright; without B it silently uses the localhost fallback, which is how B stayed hidden.

**Cause:** turbo does not pass ambient environment variables into a task unless the task declares them. Running Playwright directly (`pnpm exec playwright test`) always worked, which is what made this hard to see.

**Fix** in `turbo.json`:

```json
"e2e": { "cache": false, "env": ["BASE_URL"] }
```

**Verify:**

```bash
BASE_URL=http://your-target pnpm e2e                    # exit 0
cd apps/e2e && BASE_URL=http://your-target pnpm exec playwright test   # same result
```

Both paths agreeing is the point: before this fix they disagreed, and only the direct one was telling the truth.

## What needs no action

Everything else in 2.5.1 is plugin-internal: guards in `tests/validate.js` and the reasoning recorded alongside each fix. No `.specs/` artifact changes, no configuration changes, and nothing to do for a project on the default workspace profile with a `web` layer.
